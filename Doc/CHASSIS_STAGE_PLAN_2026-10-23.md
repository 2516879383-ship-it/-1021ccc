## 1. 本阶段目标与已确认决定

提供可被最终完整程序直接调用的底盘接口：传入车体速度 `(vx, vy, omega)`，内部生成四轮目标 RPM，并通过现有 MotorBus 发送。在它上面增加两个非阻塞动作：保持起始朝向的相对平移、原地相对旋转。

| 项目 | 已确认方案 |
|---|---|
| 坐标与单位 | 车体前方为 +x、左方为 +y、俯视逆时针为正角；平移 mm/s、角速度 °/s；距离 mm、角度 ° |
| 四轮地址 | 1 前左 FL、2 前右 FR、3 后左 RL、4 后右 RR |
| 距离/角度反馈 | 光流测距＋陀螺测角；轮子反馈负责健康、执行诊断和停车确认 |
| 速度调用 | 周期刷新，推荐每 50 ms 一次；300 ms 没有有效新命令则请求停车 |
| 有限动作 | 启动一次，主循环推进，查询结果；平移与旋转分别提供接口 |
| 混合运动 | 速度接口允许同时给出平移和角速度；首版有限动作不做同时改变位置与朝向的三自由度轨迹 |
| 测试启动 | 上电静止，屏幕点击 START 后执行一轮自动验收，不自动循环 |
| 四轮准备 | START 后检查四轮静止、健康反馈，异步使能需要使能的轮子；准备完成才开始运动 |
| 其他机构 | 5～7 轴允许未连接；本验收不使能、不移动、不回零这些轴；全局 STOP 仍按原功能停止全部轴 |
| 反馈异常 | 必需传感器失效、动作超时或电机异常：停车、锁定本轮失败，不自动恢复续跑 |
| 参数录入 | 集中配置文件＋人工测量/标定；不增加 Flash 参数保存和屏幕标定向导 |
| 实测合格线 | 300 mm 平移终点误差 ≤20 mm，90° 旋转误差 ≤5°；每项连续三次 |
| 当前实物条件 | 底盘已装好，但轮径、轮距、轴距、减速比、方向及光流标定数据尚未提供 |

## 2. 源码调查结论与最小改动边界

### 2.1 可以直接复用的基础

- `main → QrApp_Process` 是协作式主循环，现有电机通信、扫码、光流、陀螺及分步 UI 可继续运行；不增加 RTOS，不改 HAL 与时钟。
- `MotorBus_Wheels()` 已接收 FL/FR/RL/RR 四个有符号 RPM，生成 37 字节 `0xAA` 四轮速度包；UART5 保持唯一发送通道。
- 总线已有“最新待发向量覆盖旧向量”、100 ms 四轮发送间隔、速度租约、故障扩大为四轮停止、持续 STOP 重试和新反馈停车确认。
- `FlowSnapshot` 提供轴映射后的增量/累计 counts、样本序号、质量、重启分段和清零计数；尚无毫米换算。
- `GyroSnapshot` 提供角速度、相对累计角、有效性和轨迹中断标志。当前固定补偿为 15.86°/s，不等于完成真实校准。
- 屏幕已使用条带/短文本分步绘制。沿用这套机制，不引入整屏阻塞刷新。

## 3. 对外接口、非阻塞语义与控制权

### 3.1 计划公开接口

以下是待实现接口，不是当前已有 API。使用调用方持有的 `Chassis` 实例，绑定现有 `MotorBus`；时间统一为单调毫秒计数，并采用可处理计数回绕的期限比较。

```c
void Chassis_Init(Chassis *c, MotorBus *bus,
                  const ChassisConfig *config, uint32_t now_ms);
void Chassis_Process(Chassis *c, const FlowSnapshot *flow,
                     const GyroSnapshot *gyro, uint32_t now_ms);

ChassisRequestResult Chassis_Prepare(Chassis *c, uint32_t now_ms);
ChassisRequestResult Chassis_SetBodyVelocity(Chassis *c,
    float vx_mm_s, float vy_mm_s, float omega_deg_s, uint32_t now_ms);
ChassisRequestResult Chassis_MoveRelative(Chassis *c,
    float dx_mm, float dy_mm, float max_speed_mm_s, uint32_t now_ms);
ChassisRequestResult Chassis_RotateRelative(Chassis *c,
    float angle_deg, float max_rate_deg_s, uint32_t now_ms);
void Chassis_Stop(Chassis *c, uint32_t now_ms);
void Chassis_GetSnapshot(const Chassis *c, ChassisSnapshot *out);
```

- 请求结果区分 `ACCEPTED / BUSY / NOT_READY / INVALID`。ACCEPTED 只表示接受意图；具体拒绝原因保存在快照中。
- 服务状态为 `DISARMED / PREPARING / READY / VELOCITY / MOVING / ROTATING / STOPPING / FAULT`；动作结果另列 `NONE / RUNNING / SUCCESS / CANCELLED / FAILED`，不得用一个 busy 位同时表达停车是否确认。
- 快照包含状态、结果、原因、请求编号、目标速度、限幅后速度、四轮目标/反馈 RPM、局部位姿与目标误差、反馈有效性、停车待确认标志。无效测量显示 `--`，不将无效值当零。
- 所有入口立即返回，不含 `HAL_Delay`、串口等待或“直到完成”的循环。`Process` 每轮有界执行，且不直接发串口。

### 3.2 调用规则

1. 程序先提交 Prepare，持续调用 Process，等 READY；只有显式 Prepare 才检查并使能四轮，上电初始化本身不使能或运动。
2. READY 时可进入速度模式或启动一个有限动作。速度模式中每次合法更新覆盖旧目标，不累积队列。
3. 速度命令的有效期从调用时刻算起。内部重复发送同一目标不得代替上层刷新，也不能延长输入有效期；过期后清待发意图并停止。
4. `SetBodyVelocity(0,0,0)` 表示停车，不只发送零速帧后立即宣布静止。正常停车确认后回 READY；超时未续命的速度模式锁定失败，须显式 Prepare 后才能再次运动。
5. MoveRelative 的 `(dx,dy)` 使用动作开始时的车体坐标；动作内部允许横纵向修正并保持开始朝向。RotateRelative 使用有符号相对角，不把 +270° 自动改成 -90°；首版允许范围为 ±360°。
6. 有限动作运行中拒绝其他运动请求，不能用一个新速度请求悄悄覆盖动作。正常完成后回 READY，保留 SUCCESS，直到下一次明确请求。
7. Stop 始终优先，取消当前动作/验收序列及待发运动。停车未确认期间禁止新动作；故障恢复不自动重放。

### 3.3 仲裁与其他模块

- 底盘准备、运动、停车或自动序列段间等待期间，验收流程持有四轮控制权。UI 的单轮使能、速度、四轮组和同步动作不得抢占；给出 `CHASSIS BUSY`。
- 用户 STOP 取消底盘意图后再进入现有 MotorBus 停止流程，防止下一轮 Process 又补发运动。STOP AXIS 若指向 1～4，也取消底盘并停四轮；全体 STOP 保持原有全轴语义。
- 保留切页查看状态。闭环动作或自动序列持有控制权时，拒绝 FLOW CLEAR、GYRO ZERO/CAL 等会改变测量基准的操作；底层若仍检测到基准改变，应立即中止动作。
- 最终任务程序通过底盘接口调用四轮，不再同时直接调用 MotorBus 的四轮运动入口；5～7 轴仍走现有接口。首版不新增通用多生产者调度框架。

## 4. 算法与调度方案

### 4.1 麦轮逆运动学

首版采用标准 X 型滚子布置，先通过实物轮序和滚子方向核对确认。轮子的左右安装方向通过独立的电机符号配置解决；如果实际不是该布置，先修正机械安装或明确变更模型，不能靠随意反转某一项掩盖错误。

设轮半径 `r`、前后轮中心距离 `L`、左右轮中心距离 `W`，单位均为 mm；`k=(L+W)/2`。将输入角速度换为 `w=omega*pi/180`，轮缘速度为：

```text
FL = vx - vy - k*w
FR = vx + vy + k*w
RL = vx + vy - k*w
RR = vx - vy + k*w

motor_rpm[i] = wheel_linear_speed[i] * 60/(2*pi*r)
               * gear_ratio * motor_sign[i]
```

`gear_ratio` 定义为电机转数/轮子转数，直连填 1。`motor_sign[i]` 表示让该轮产生车体前进作用时对应的协议 RPM 正负号，不能照搬开源项目的 dir 位。

- 拒绝 NaN、无穷值及无效配置。机械未确认时拒绝任何底盘运动请求。
- 先限制平移向量长度和角速度，再算轮速。任一轮超出配置 RPM 上限时，四轮统一比例缩放，保留组合运动比例；不逐轮独立裁剪。
- 发送前做对称四舍五入到整数 RPM，零附近不人为加入最低转速“踢一脚”。快照保留浮点期望值和量化后目标，便于区分量化误差。
- 平移/角速度采用限加速度变化；正常反向经过零附近。紧急/故障 Stop 绕过软件平滑，直接交给既有停车策略。

### 4.2 光流和陀螺构成短程相对里程计

本阶段只维护动作起点附近的相对位姿，不建立比赛全局定位、地图或融合滤波器。

1. 新动作记录当时有效光流累计值和陀螺角度为基准；不清零共享服务。
2. 将光流 counts 差值通过独立 X/Y 毫米系数及安装朝向转换到车体坐标。这里的输入是 Flow 服务已经应用 `FLOW_SWAP_XY/FLOW_*_SIGN` 后的数据，避免重复换轴。
3. 使用与光流样本时刻对应的陀螺角度，把平移增量旋转到动作起始坐标系。保留最近两个有效 gyro 样本作时间对齐；不得用任意年龄的当前角度套用旧光流增量。没有可用时间配对时等待下一新样本，超过光流有效期则失败，不外推填补测量缺口。
4. 配置光流传感器相对底盘旋转中心的 `(offset_x,offset_y)`；从测得的传感器位移中减去该偏置随姿态旋转产生的位移。采用相邻姿态旋转矩阵之差计算偏置项，平移方向取区间中间朝向。
5. 用序号去重；累计差值可吸收同一连续有效区间内未逐次消费的 counts，但不能跨越 rejected、gaps、segments、clears 或溢出变化。gyro 的断轨、ZERO、重新校准/重启同样使当前动作失效。

平移闭环同时要求光流和 gyro 有效；原地旋转只要求 gyro 有效，不因单独光流质量不足阻断旋转。直接速度模式不依赖光流/gyro 可用性，但仍要求四轮健康反馈，且不承诺保向或实际地面速度闭环。

### 4.3 短程闭环控制

使用“位置比例控制＋接近目标减速＋输出限加速度”，不直接复制参考项目 PID 参数，也不先加入积分项、复杂轨迹规划或 EKF。

- 平移：计算起始坐标系下的位置误差，使用向量比例控制；速度幅值再受用户上限和 `sqrt(2*a*remaining_distance)` 制动包络限制。变换回当前车体系后输出 vx/vy。
- 保向：以开始朝向为目标，用角误差比例项与实测角速度阻尼项生成 omega；限幅后与平移统一进入麦轮解算。
- 旋转：有符号累计角误差生成 omega，使用比例/角速度阻尼及角向制动包络，vx/vy 为零；不宣称此时车体旋转中心完全无漂移。
- 首版调试初值：位置 Kp=1.5/s、角度 Kp=2.0/s、角速度阻尼系数 0.2；无积分、无误差差分 D 项。它们是待实车验证的控制初值，不是标定值。
- 内部到位窗：平移误差模长 ≤10 mm、朝向误差 ≤2°，旋转误差 ≤2°，实测角速度绝对值 ≤3°/s；新鲜测量连续满足 200 ms 后请求停止。
- **SUCCESS 必须等四轮停车确认后再给出**，并用停稳后的有效测量复查误差。超出内部窗口则报告未达标，不自动推进下一段，也不把 ACK 当到位。
- 每段运行期限使用 `5 s + 3*理论匀速时间`，平移按距离/速度、旋转按角度/角速度计算；限制在 5～60 s。到期停止并失败。停车确认超过现有 3 s 阈值后仍保留未确认停止及重试，不以超时当作已停。

### 4.4 周期、租约与阻塞边界

| 项目 | 首版默认 |
|---|---|
| Chassis_Process | 每轮主循环调用，先处理 Stop/故障/输入过期，再决定是否计算控制 |
| 控制计算 | 最多每 20 ms 一次，使用实际 dt；不补跑积压的多个控制周期 |
| 四轮速度发布 | 最多每 100 ms 一次，复用 MotorBus 最新值槽位 |
| 上层速度刷新建议 | 50 ms；输入命令 300 ms 到期 |
| 内部速度租约 | 最长 300 ms；直接速度模式不得晚于输入命令原始截止时间 |
| 平移/角速度上限 | 首版 100 mm/s、30°/s；低速地面验收初值 |
| 平移/角加速度 | 首版 200 mm/s²、60°/s²；需通过停距试验验证 |
| 驱动加速度字段 | 初版沿用现有测试值 100，作为独立驱动参数，不将其误称 mm/s² |
| 反馈时效 | 保留底层电机 1600 ms 新鲜度门限；光流 ≤100 ms、gyro ≤30 ms，另要求各自有效/连续性标志成立 |

直接速度命令剩余有效期不足 MotorBus 允许的最短 100 ms 租约时，不再排入会跨过截止时间的新包；到期立即发起停止。底层接受但未发送不等于已生效，发布统计须区分请求接受与实际提交。

每轮实际发送仍由 DMA/应答/查询调度决定，100 ms 是发布上限，不是硬实时到轮保证；记录发布间隔、反馈年龄与拒绝原因。总线忙时保留最新目标，不忙等；若旧租约到期或健康条件丢失，停止，不无限延租。

新增层不再加入耗时外设操作。现有 I2C/SPI 仍有有界同步访问，因此应称“动作非阻塞、主循环协作”，不能宣称整个固件零阻塞。保持当前 gyro 多次服务与 UI 分片节奏，新增计算前后必要时刷新 AppClock。

软件超时停车依赖 MCU 继续执行且通信能够恢复；300 ms 是发起停止的时限，不是实物必定停稳时间，也不是电机端硬件看门狗。

## 5. 参数、标定与实机放行

### 5.1 集中配置，未知参数不伪造

计划在 `User/chassis/chassis_config.h` 集中配置：

| 参数 | 获取方式与初始策略 |
|---|---|
| 有效轮径、L、W、减速比 | 实物测量/传动核对；未知置 0，使运动配置无效 |
| 四轮方向、X 型布置确认 | 架空单轴低速核对，分别记录正向；未确认不得开启四轮运动 |
| RPM 上限 | 开发默认 60 RPM，且不得超过现有协议 3000 RPM；这是保守软件上限，不代表电机/机械已验收能力 |
| 光流 X/Y mm/count、安装角度 | 在实际地面、安装高度下人工已知距离正反向标定；未知尺度置 0 |
| 光流中心偏置 x/y | 测量光学中心相对底盘几何旋转中心的距离与符号；不得默认“安装在中心” |
| gyro 轴向、符号与角度比例 | 核对现有配置，实物转动已知角度确认；固定偏置继续沿用，未获得新证据不自行替换 |
| 机械确认、闭环反馈确认 | 分开两个显式配置标志：前者放行速度接口，后者放行距离/角度动作与自动验收 |
| 控制与验收参数 | 速度、加速度、增益、到位窗、超时、段间等待统一放在此处 |

示例/模拟配置只放在测试中。默认固件在实物参数未确认时显示 `CONFIG REQUIRED` 及具体缺项，START 拒绝并保持静止；这属于“软件可构建、待标定”，不能宣称地面验收已经完成。

### 5.2 人工标定顺序

1. 核对 1～4 地址、物理轮位、滚子 X 布置及传动比；架空用现有单轴点动记录每轮正向。无轴反转需求时不扩展 UI；若现有单向点动不足，用受控测试配置验证反向并记录，不启用整车自动序列。
2. 测量轮径、L、W、光流安装高度和旋转中心偏置；填写机械配置，先做架空四轮向量/STOP 检查，确认 `0xAA` 在实物上按预期工作。
3. 保持实际安装高度和场地表面，人工无旋转地沿前后、左右各移动 500 mm，每方向至少三次，记录光流 X/Y 累计差值、质量和 rejected/gaps。根据主轴读数确定 mm/count 与安装方向；若有显著交叉轴残差，先校准安装角度，不能只改比例。
4. 使用现有固定补偿记录静止 10/30/60 s 漂移，并测正反 90° 至少三次。首版放行目标：静止 30 s 漂移 ≤3°、单次 90° 测量误差 ≤3°；不达标时保留阻断，先处理偏置/安装/采样问题，不用 ZERO 假装消除漂移。
5. 用已知旋转检验光流偏置补偿，观察纯旋转是否产生明显虚假中心平移；记录误差。确认后放行闭环，开始低速短程调参和三次完整验收。

当前缺少的数据由用户后续测量提供。实现者可以完成接口、测试、诊断和文档，但没有这些数据不能选择一组猜测尺寸作为实车交付参数。

## 6. 选定的最终运行效果

### 6.1 屏幕与启动

保留上电 QR 页和现有四类诊断页。从 MOTOR 概览标题区域增加明确的 `CHASSIS` 入口，进入独立底盘视图；BACK 返回 MOTOR。继续提供 GYRO/FLOW 查看入口，不大改现有页面结构。

底盘视图显示：准备/配置/运行状态、验收段号和名称、目标与当前相对位移/角度、目标 vx/vy/omega、四轮目标和实测 RPM（必要时切详情）、传感有效性、最后拒绝/失败原因和停车确认状态。采用 ASCII 与现有 Font16，不引入中文字库。

START 为按下边沿触发；运行中重复触摸不重置目标、不清计时。STOP 在任意页可用。切页只改变显示，不停止后台采样与运行。验收结束显示 `DONE`，取消显示 `CANCELLED`，异常保留具体原因；失败后的 START 必须重新通过准备检查，且不得绕过尚未确认的停车。

### 6.2 一轮固定验收序列

START → 参数/反馈检查 → 异步四轮使能 → 下列八段 → DONE。各段确认停稳后额外等待 1 s，再启动下一段；段间保持健康检查，异常终止。

| 段 | 动作 | 目标 |
|---|---|---|
| 1 | 前进，保持开始朝向 | `(dx,dy)=(+300,0) mm` |
| 2 | 后退，保持开始朝向 | `(-300,0) mm` |
| 3 | 左移，保持开始朝向 | `(0,+300) mm` |
| 4 | 右移，保持开始朝向 | `(0,-300) mm` |
| 5 | 左前斜行，保持开始朝向 | `(+200,+200) mm`，路径约 283 mm |
| 6 | 右后斜行，保持开始朝向 | `(-200,-200) mm` |
| 7 | 原地逆时针旋转 | `+90°` |
| 8 | 原地顺时针旋转 | `-90°` |

每段目标均相对该段开始的实际姿态，不把前段预期终点伪装成实际起点。成对动作便于观察回位，但不保证累计回到最初起点；记录最终回位误差。

只连接四轮时可执行，不要求 5～7 轴在线或机构回零。四轮准备总期限 10 s；缺轮、非静止、保护/堵转、未确认停车、使能失败均拒绝开始，不跳过缺轮继续执行。

## 7. 验证、验收与不达标处理

### 7.1 软件测试

- **运动学：**正负前进、横移、四个对角、正反转、混合速度；几何/减速比换算；独立电机符号；统一比例限幅；零、微小值、负数舍入、NaN/Inf、无效配置。
- **服务：**上电不运动；Prepare 的健康/静止门控和使能确认；重复请求、互斥、计时回绕；新目标覆盖、不积压；输入过期、零向量、Stop 抢占；忙总线不延长旧租约。
- **真实 MotorBus 联合替身：**连续变速、10 Hz 发布与轮询并行；四轮在线而 5～7 离线；地址 1 ACK 缺失；任一轮故障；停止首帧丢失重试；停车未确认时无运动重放。不能只用一个始终返回成功的发送桩。
- **里程计：**尺度/安装旋转、偏置补偿、跨角度零点、gyro/flow 时间对齐、重复序号、累计差值；清零、重启、拒收、过期及缺口必须使动作失败；原地转动不得虚构中心平移。
- **控制闭环：**使用独立车体模型模拟直行、横移、斜行、转向、惯性和测量延迟；验证减速、误差收敛、有限时间退出。加入轮速量化、卡住不动、传感失效，避免用“测量值直接等于目标值”冒充闭环测试。
- **动作结果：**只有到位窗口稳定并确认停车后 SUCCESS；停稳后越界不成功；异常锁定、重新 START 重新检查；有限动作中途不允许速度调用抢占。
- **界面/应用：**启动边沿、重复点击、配置缺失说明、四页切换、全局 STOP、动作期间禁止测量清零；保留带绘图耗时的多外设并行测试，确认未新增 gyro GAP、扫码饿死或越界绘图。
- **构建：**全量主机测试通过，Keil `LCD` 目标 0 error/0 warning；检查栈/RAM 增量，保持 AC5 可编译。

原上电逐轮测试已经被用户要求删除，未来测试应验证“无自动运动＋显式启动新序列”，但不能连同旧测试中的 UART 故障、STOP 和多外设并行覆盖一起丢弃。

### 7.2 实机验收

先完成标定和架空方向/聚合包验收，再在实际地面连续运行三轮八段序列。使用尺、地面标记和角度参考进行外部测量，不以程序自己显示的误差作为唯一合格依据。

- 每段 300 mm 平移终点欧氏误差 ≤20 mm；斜行段终点欧氏误差同样 ≤20 mm，平移朝向误差 ≤5°。
- 每段 90° 旋转误差 ≤5°；额外记录旋转中心漂移、停止耗时及整轮回位误差，不将未约定阈值的指标写成已合格。
- 三轮中每一项都满足才记通过，记录所有失败样本。每次包含固件版本、配置、载荷、地面、传感器高度、命令目标、外部实测、UI 状态和异常原因。
- 操作 STOP、停止上层速度刷新、受控屏蔽反馈，确认不会继续下一段。断链时只记录实际停车能力和恢复行为，不宣称通信完全中断仍能保证机械停车。
- 运行中可切换查看扫码、各电机、光流、陀螺状态；底盘之外的服务继续工作。

### 7.3 未达标时的修正顺序

1. 方向错误、横移变旋转：先检查轮序、滚子、方向符号和单位，不调 PID 掩盖安装错误。
2. 位移比例错误、转动产生平移：先查光流高度/地面/尺度、时间对齐与安装偏置。
3. 平移跑偏、转角漂移：先核实 gyro 残余偏置及采样连续性；不自动放宽有效性门限。
4. 过冲或来回震荡：先降低速度、检查 10 Hz 实际发布延迟和驱动加速度，再调整比例/阻尼及制动参数。
5. 仍不达标时交付测量与失败原因，保留运动接口但不宣称闭环通过。只有证据表明现有模型不足，才另行评估小范围算法升级；不在本阶段无依据引入复杂融合或大幅总线重构。

## 8. 开源参考取舍与实施交接

已阅读本地“一点创绘”的 `mecanum_wheel.c`、`mecanum_imu_move.*`，以及西安理工大学方案的 `chassis_control.c`。

- 不直接复制：轮序、方向位、把 omega 当 RPM 等效量的接口、逐轮独立限幅、阻塞 `HAL_UART_Transmit/HAL_Delay/osDelay`，以及未经本车测量的 PID 和速度常数。
- 标准运动学负责从车体速度计算轮速；光流/gyro 闭环负责修正实际车体误差，两者各司其职。先证明标定和低速短程效果，再决定是否需要更复杂算法。

后续实施顺序固定为：**配置与纯运动学 → 非阻塞四轮准备/速度服务 → 短程里程计 → 平移/旋转动作 → 自动验收与 UI → 故障/并行回归与 Keil 构建 → 人工标定、实机三轮验收 → 更新交付记录。**
