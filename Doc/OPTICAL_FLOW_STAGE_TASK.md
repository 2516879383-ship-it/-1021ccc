## 4. 电气、引脚与 SPI 接入

### 已核对资料事实

- 芯片采用四线 SPI；本地手册给出的 SCLK 上限为 2 MHz，NCS、NRESET、MOTION 均低有效。
- 芯片 VDD 为 1.8～2.1 V，VDDIO 为 1.8～3.6 V。模块原理图中 VCC 经板载 1.8 V 稳压支路供 VDD，且 VCC 直接供 VDDIO；因此按该图采用 3.3 V 供电与逻辑，不能因“有稳压器”就把模块 VCC 接到 5 V。
- 图中 JP1：1=VCC、2=GND、3=MOSI、4=SCLK、5=MISO、6=CS、7=RESET、8=MOT、9=VREG。此编号仅对应该原理图，实际接线仍应对照模块丝印/版本；VREG 是芯片内部电压输出，不作为外部供电入口。
- 原理图 RESET 有上拉。首版可轮询采样、暂不使用 MOT 中断；RESET 是否由 MCU 控制应明确记录，未连接时仍须保证其电平及软件复位流程正确。
- 手册建议工作距离下限为 80 mm，照明和表面条件会影响测量。用户尚未确认实际离地高度、方向、地面材质和标定系数，不能默认低于 80 mm 的安装也可靠。

### 实施时必须给出的接线表

为 VCC/GND/SCLK/MOSI/MISO/CS 及可选 RESET/MOT 列出“模块丝印、MCU 引脚、核心板排针及脚号、方向、配置、核对依据”。本任务书不虚构已确定的 MCU 接线。

优先选择核实空闲且核心板引出的硬件 SPI，CS 用普通 GPIO 软件控制；不要只因芯片支持某组复用就认为板上可用。核对野火 F429 挑战者 **V1 核心板**原理图和最新 BSP，避免占用 LCD、FMC、触摸、调试与已有串口。

| 现有资源 | 必须保持 |
|---|---|
| UART5 / 电机 | PC12、PD2；DMA1 Stream0/7 Channel4 |
| USART3 / 扫码 | PB10、PB11；DMA1 Stream1 Channel4 |
| 扫码触发 | PB12，当前 1000 ms 周期 / 800 ms 低电平；不能把常用 SPI2 NSS 的 PB12 直接改成 CS |
| 调试 | USART1 PA9/PA10 |
| 触摸 | PH4/PH5，PD11/PD13 |
| 显示 / SDRAM | 沿用 LTDC、DMA2D、FMC 的全部现有引脚 |
| 板载 SPI Flash | BSP 使用 SPI5 PF7/PF8/PF9，CS PF6；即使当前应用未调用，也不能当成未连接的空闲线 |

不为光流移动已有串口或引脚。首版优先用有严格时间上限的短 SPI 事务，不强制引入 DMA/EXTI，避免新增共享中断和 DMA 冲突。只有测量表明需要异步传输时才增加相应资源。

SPI 模式、MSB 顺序、读写地址位及 CS 时序逐项按完整资料/原始驱动核对。初始化模式以核对后的 Mode 3 为起点；计算实际 SPI 内核时钟及分频，不能把 180 MHz 系统时钟当作全部 SPI 的输入时钟。建议先取不超过 1 MHz 的调试值，最终始终不超过本地手册 2 MHz。

手册已列出读地址到数据至少 35 μs、写后 CS 保持至少 35 μs、写间隔至少 45 μs、读后间隔至少 20 μs等约束，具体起止边沿按原表实现，不仅设置 SPI 波特率。微秒延时需明确时基和回绕处理；不重配置 SysTick，不长时间关中断。长等待使用时间状态机，不用散布的 HAL_Delay 阻塞整车。

## 6. 初始化、采集与数据语义

1. CS 空闲拉高，按完整序列执行复位、识别、优化寄存器写入、必要清读与稳定等待。期望 Product_ID=0x49、Inverse_Product_ID=0xB6；Revision_ID 记录读回值，不将表中复位值当作唯一版本门槛。
2. 完整初始化按有序步骤执行，保留寄存器页切换和等待；读到正确 ID 不代表已经可发布有效运动。本地手册列出复位到有效运动至少 50 ms，具体启动还须满足所选完整序列。
3. 建议采样起点 100 Hz，显示约 10 Hz；均可配置，属于待验证目标。记录实际采样间隔、最长延迟和失败次数，无法达到时说明原因并调整，不虚报实时性能。
4. 优先采用经完整资料核对的 Motion Burst；若用逐寄存器方式，必须核实读取顺序、锁存和清除规则，保证 X/Y 及高低字节属于同一测量。不能假设读两次得到同一份增量。
5. dx/dy 按芯片规定组装为有符号 16 位数据，明确低/高字节次序；不用 C 位域或结构体直接映射线上的字节布局。各质量字段、Motion 标志及快门单位按所选资料解码。
6. 每个成功且有效的样本只累计一次。UI 刷新只读快照，不再次读芯片、不重复积分；丢失或无效样本不按上一帧速度补齐。读取已消耗数据但事务失败时记录间隙，不盲目重读后当作同一帧。
7. 建议用 int64_t 累计计数，仍需明确溢出边界及显示格式兼容 AC5。原始计数保留传感器坐标；安装方向交换/反号配置与原始量分开，正负方向通过实物沿两个方向移动确认。
8. 状态/质量异常、SPI 错误、非法 ID、长期无新有效数据时使相应数据无效，不将总线全 0 或全 FF 解释成静止正常。SPI HAL_OK 只说明主控完成传输，不证明外设在线；结合周期身份检查和合理状态判断断连。
9. 质量阈值只能来自可追溯资料或明确标成待实测配置；保留原始质量与拒绝原因。不以“非零位移”作为有效性的必要条件，也不靠任意阈值证明精确定位。
10. 故障采用有限重试和退避，恢复后完成初始化并丢弃不确定的首段数据；保留或清空累计的策略必须可见。建议保留累计并标记测量中断/新段，不把断连期间丢失的位移补出来。
11. 清零仅重置软件累计及相关统计基准，不复位电机/扫码。以已消费的最后样本定义清零边界，后续样本正常累计；若要求严格按按钮时刻分段，必须额外定义传感器内部累积数据的处理，不能默认精确。
12. 初始化长等待和运行重试均分步进行；短 SPI 等待有明确超时及单次处理预算。不得使用 HAL_MAX_DELAY、运行期忙等数十毫秒、连续循环补读所有错过周期或在中断里绘图/打印。

本阶段不宣称计数等于 mm、计数/秒等于 mm/s，累计计数也不是地图位置。安装高度、地面纹理、光照、姿态与车体旋转均影响结果。可以提供固定高度、已知直线距离、双向重复的后续标定步骤，但没有数据就不填换算系数，不以电机脉冲数代替地面位移标定。

|---|---|

| 未接光流上电 | 显示 NOT FOUND/INIT ERROR 及原因，按配置低频重探测；其余功能仍可操作，不停在初始化死循环。 |

| 在适用高度、纹理和光照下静止 | 数据仍按周期刷新，位移一般接近零但允许噪声；不能承诺永久绝对零或以未刷新数据冒充静止。 |
| 沿两个方向手动平移模块/车体 | 对应 dx/dy 出现变化，累计计数变化；反向移动能观察到符号变化。记录实际轴向关系，不提前把传感器 X/Y 标成车体前后左右。 |
| 点击 CLEAR | 软件累计从明确的新基准重新统计，后续运动继续更新；不清掉扫码任务、不改变电机模式。长按不反复清零。 |
| 切回 QR/MOTOR | 光流后台采集继续；扫码锁定/重扫、电机查询、启动测试与 STOP 保持既有行为。切页不触发运动。 |
| 遮挡、表面不适合或质量下降 | 若质量/状态判据识别到异常，显示 LOW QUALITY/INVALID，停止把该样本计入有效累计；保留诊断值。未被判据识别的误差应在实测局限中说明，不保证所有不良表面都可自动检出。 |
| 断连、SPI 失败或数据过期 | 显示 ERROR/STALE，不把旧值显示为当前有效测量；记录失败及测量间隙，已有功能继续运行。 |
| 故障恢复 | 重新识别/初始化后恢复新样本，显示累计存在中断；不自动补位移、不重置或重发电机动作。 |

## 8. 实施顺序与验收

### A. 资料和资源确认

补全初始化依据；确定接线与 SPI 分频/模式/时序，形成占用表。说明采用的初始化版本和数据读取方式。在引脚未核对前，可先完成纯协议/服务测试，不凭猜测把具体 GPIO 写入事实文档。

### B. 独立驱动与服务

完成初始化、ID 检查、解析、周期调度、累计、清零及失效/恢复。以假时钟和 SPI 替身验证以下行为：

- 正常 ID、错误 ID、全 0/FF、SPI 超时；失败不会阻塞主循环。
- 初始化寄存器顺序、页切换、必要等待和未完成前不发布有效数据。
- dx/dy 正负值、0、32767、-32768、字节序与坐标映射。
- 样本只消费一次；多次 UI 读取不累计；清零边界与长按处理。
- 有效静止、低质量、过期、部分读取失败、错过周期、计时回绕、累计边界。
- 断连后失效、退避重试、重新初始化和恢复段标志；不伪造丢失位移。
- CS 释放及事务时序，异常路径也能恢复总线；不能只测试函数返回常量。

### C. 最新工程集成与回归

接入实际主循环和 FLOW 页、Keil 工程及现有测试脚本。小块合并电机开发的最新变更；验证 FLOW 操作不误触发电机枚举动作，电机 STOP 在光流页可访问。

在最终集成目录执行现有主机测试与完整构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Scripts/build.ps1 -Rebuild
```

要求现有及新增测试通过，Keil 0 错误、0 警告。当前脚本已覆盖电机启动测试，不删除既有断言以适配光流。核查程序/静态 RAM/栈开销；若引入 DMA，另查 DMA 可访问内存和共享回调，不让缓冲进入 CCM。

测量或模拟同时采样、持续扫码、触摸切页、七机查询/动作与停止请求的场景；报告光流处理最长耗时、实际采样间隔、漏采/错误计数及原功能回归。硬件 SPI 时序和真实调度抖动需要逻辑分析仪/实物检查，主机替身不能替代。

### D. 实物验证另列

1. 对照实物版本接线；核实 3.3 V、电源地、CS/RESET 状态、SCLK 及读写时序，记录真实 ID。
2. 记录安装高度、光照、表面、方向及采样配置；做静止、X/Y 正反向和重复移动。
3. 检查清零、切页后台采集、断连/恢复及不良表面表现，保留屏幕/串口/波形证据。
4. 与扫码和七电机同时运行，确认 STOP 可用、扫码不中断、光流失败不拖住主循环；记录实际延迟和误差。
5. 若尚无实物条件，完成软件与构建并给出逐步联调清单，将上述项目标为待实测，不能写“光流定位精度已达标”。
