## 3. 工程方式：直接补充 HAL 初始化

**本阶段不从头重建 CubeMX 工程，不用新生成工程覆盖现有文件。**

依据：

- 当前项目已采用 C/HAL BSP 初始化，工程内没有对应 `.ioc`。
- 已有 180 MHz 时钟、LTDC、SDRAM 和触摸配置；加入一路串口不要求重建这些部分。
- 仓库 HAL 为 1.7.3，当前未提供 `HAL_UARTEx_ReceiveToIdle_DMA`。采用现有 HAL 支持的接收方式，不直接复制新版 HAL API 或整体升级 HAL。

“手写初始化”指按本工程 HAL 完成外设/GPIO 时钟、复用、UART 参数、DMA、NVIC 和回调分发，不是另写底层寄存器库。可用 CubeMX 在独立目录辅助检查引脚或生成参考，但不把辅助 `.ioc` 描述为当前工程的完整配置源。

候选方案：USART3，PB10 TX、PB11 RX，AF7；PB11 在野火资料中还标为 RMII_TX_EN，需核对核心板引出脚及实际占用后定稿。先核对当前 LCD/SDRAM/触摸和所有已启用外设，不依据 MCU 有复用功能就认定能直接接线。

优先使用循环 DMA RX + IDLE/半满/全满事件 + 软件缓冲。USART3 RX 的 DMA1 Stream1/Channel4 可作为待核对候选；现有 UART5 占用 Stream0/Stream7、Channel4，禁止覆盖它们。最终映射应以对应芯片 DMA 表和工程占用核定。

HAL 全局回调只能保留一套入口：

- `HAL_UART_MspInit` 在 `bsp_debug_usart.c`，已有 USART1/UART5 分支，新增 USART3 分支。
- RX 半满、全满、错误、TX 完成回调当前在 `bsp_motor_uart.c`。可抽出小型公共分发文件，也可保留入口并按实例转发；不得新增同名强定义或删除 UART5 路径。
- 新 IRQ 不得与旧 IRQ 重复定义，优先级应保证电机收发不被扫码处理长时间阻塞。
- DMA 缓冲放在 DMA 可访问的片内 SRAM，不能放 CCM。

### C. 组帧与任务校验

1. UART IDLE 只是数据暂时空闲，不直接等同一条二维码结束。支持任意拆分和多条数据同批到达。
2. 首版按已确认的 CR、LF 或 CRLF 结束符形成完整记录；CRLF 不计为两条消息。
3. 完整任务负载恰好 15 个 ASCII 字符：`ddd+ddd+ddd+ddd`。用于保存字符串的缓冲至少 16 字节；接收帧缓冲须另留容量，不能等同字符串长度。
4. 第 1/3 组颜色为 1～6，每组内不重复，两批颜色集合一致；第 2/4 组分别为 1、2、3 的排列。输出四个数组及原始规范化字符串。
5. 不从任意长噪声中随意截取一个“看起来合法”的 15 字符片段。带额外字符、错误位置、非 ASCII、过长或截断的完整记录明确拒绝。
6. 超长/溢出后丢弃受损记录，等待可靠边界再恢复。超时丢弃未完成帧，不能把下次扫描拼接到旧半帧。
7. 如果实物确实无结束符，单独定义且测试无结束符模式：长度检查与可配置接收间隙共同确定边界；不得刚收到第 15 个字符就接受更长报文的前缀。说明这种模式的边界限制，优先建立带结束符的输出契约。
8. 任何模块命令 ACK 与任务文本分开处理；ACK 不能当扫码结果。首版不需要命令时，不臆造 ACK 格式。

任务码示例 `156+123+516+231` 的输出应为颜色 `[1,5,6]`、位置 `[1,2,3]`、颜色 `[5,1,6]`、位置 `[2,3,1]`。第四组只表示第二批粗加工位置，本阶段只解析，不生成码垛动作。

### D. 状态和显示

- 区分“串口初始化成功”“收到原始字节”“完整记录合法”“等待扫描超时”，无扫码输出不等于模组离线。
- 保存最近一次有效码、接收时间、有效记录序号、非法记录/溢出/UART 错误计数。
- 非法新数据不得覆盖最近有效结果；同时显示本次错误，不能让历史有效码看起来像本次新扫描成功。
- 提供开始/重置扫描会话的接口：每次会话至多接受一次任务结果；重复输出只更新接收统计或重复计数，新会话允许再次扫描同一码。本阶段按下面的主程序现象定义锁定结果，不在调试显示中另行替换为后来扫到的码。
- 屏幕完整显示 15 字符，可分两行；保持触摸和电机状态入口。刷新采用限频/局部更新，不通过大量阻塞 printf 显示接收数据。
- 本阶段验证 480×272 边界、文本完整和无残影；赛事要求的 12 mm 实物字高与安装位置必须另行测量，不把“能显示”记为比赛显示验收通过。

### E. 阶段完成后的主程序现象定义

本节是下一对话实现与实物验收的目标行为，尚未实现。默认使用现有英文字库，英文标签与下表含义对应即可，不要求新增中文字库。

**默认操作流程：上电自动开启一次接收会话 → 等待合法任务码 → 显示并锁定结果 → 点击 RESCAN（重新扫码）开启下一次会话。**

这里的“开启会话”表示主控开始接受本次结果；模组光学扫描是否需要触发，按实际模块模式落实。连续/感应模式下主控等待其输出；需要触发的模式下，在会话开始时执行已经核实的触发操作。不得仅设置一个软件标志，就宣称已经触发模组扫描。

| 场景/操作 | 屏幕可见现象 | 程序行为 |
|---|---|---|
| 上电初始化完成 | 默认进入二维码页，状态 `WAIT CODE`，任务码区域为 `--`；显示 `RESCAN` 和 `MOTOR` 触摸按钮 | 自动开启第 1 次会话，不需要先按启动键；初始化失败则显示 `UART ERROR`，不能伪装为正常等待 |
| 尚未扫码 | 保持 `WAIT CODE`，显示等待时长或接收统计；触摸与页面切换仍响应 | 不产生任务成功事件，不把静默当成设备离线；后台继续电机只读查询 |
| 扫描合法示例 `156+123+516+231` | 状态改为 `VALID / LOCKED`，完整显示 `156+123+516+231`；可分两行但保留三个加号 | 一次性发布完整解析结果和本次有效标志；本会话只产生一次接受事件，结果保持到重新扫码或复位 |
| 锁定后再次扫相同码 | 任务码及锁定状态不变，可增加重复计数 | 不重复发布任务成功事件 |
| 锁定后扫到另一合法码 | 仍显示本次锁定码，可提示 `IGNORED / LOCKED` | 不替换已接受的任务；需要新任务时使用 RESCAN |
| 等待中扫到非法码 | 主状态继续等待，错误区域显示 `INVALID CODE` 及简短原因，错误计数增加 | 拒绝该记录，继续接受后续扫描；不生成有效任务。底层最近有效历史记录保留，但不能显示为本会话成功 |
| 会话开始后 10 秒仍未取得合法码 | 显示 `WAIT TIMEOUT`，表示本次尚未取得有效结果 | 10 秒为本阶段可配置联调默认值，不是比赛规则；不退出接收、不判离线、不自动反复发送触发命令。稍后收到合法码仍可成功 |
| 点击 RESCAN | 当前任务区域清为 `--`，状态回到 `WAIT CODE`，本次等待计时归零 | 新会话编号加一、当前有效标志清零、解除锁定；清除旧的未完成记录与已排队旧结果，建立新接收边界。历史有效记录可在内部保留；累计错误/接收计数不清零 |
| 新会话再次扫相同码 | 可再次显示 `VALID / LOCKED` | 允许接受与上一会话相同的内容；去重不能跨会话永久屏蔽该任务码 |
| UART 错误或接收溢出 | 错误区域显示 `UART ERROR` / `RX OVERFLOW`；已有锁定码仍保留，等待中的会话不误显示成功 | 丢弃受损半帧，恢复接收并重新寻找完整记录边界；恢复本身不产生成功事件，也不改变电机状态 |
| 拔掉数据线、没有任何新字节 | 等待中的会话按上面的等待/超时规则显示；锁定后的码继续保留 | 单凭静默无法识别拔线，不虚构在线/离线结论；重连后可恢复接收，旧半帧不能拼入新记录 |
| 点击 MOTOR / 返回 QR | 切换电机只读状态页和二维码页，显示当前页面真实数据 | 切页不重置扫描会话、不解除锁定，二维码接收持续处理；电机页面标明只读，不显示演示正在运行，不提供运动按钮 |
| 复位/重新上电 | 从 `WAIT CODE` 和 `--` 开始 | 本阶段不将任务写入 Flash；锁定结果和会话状态不跨复位恢复 |

RESCAN 每次有效点击只开始一次会话，长按不得连续重置。若复用现有触摸驱动，仍需实现按钮命中与按下/释放事件，不能只显示按钮图形。切页和 RESCAN 都只影响扫码/显示，不驱动电机。

重新扫码应舍弃会话开始前已进入本机缓冲的字节，随后等待可靠的新记录边界。普通文本没有模组侧会话编号，因此不能承诺区分所有“模组内部滞留、之后才输出”的旧结果；若实际存在这种情况，需结合已核实的停止/重新触发机制解决，并记录限制，不用主控会话编号冒充线上事务标识。

屏幕布局至少提供：任务码区域、会话状态、错误/接收统计、RESCAN 和 MOTOR 按钮。错误提示不得覆盖任务码；返回 QR 页应重绘当前快照，清除旧文字残影。整个阶段均不调用电机自动演示、不因任何二维码事件发送运动/使能/失能指令；演示源码与配置完整保留。
