# TTL → CAN 总线迁移假设性计划书（F429＋7 电机）

编写日期：2026-10-23。核对基线：`E:/工创赛/迁移野火板`，main `e04f31d`，以及当前工作区 README。本文是**待决策、待实施的假设方案**，不是交付报告，不代表工程已切换 CAN 或实物已验收；当前状态仍以 [README](../README.md) 为准。

本轮只核查源码、官方资料并编写计划，未修改运行代码、固件配置或接线，未编译、烧录。此前工作区已有 README 修改和两份新计划，本计划不覆盖它们。

## 1. 结论与范围

可以在现有 F429 工程上迁移，无须重建 CubeMX 工程、换主控或整体升级 HAL。建议保留 Emm 命令构造、MotorBus 七轴状态机和应用接口，新增 CAN BSP 与分包适配，局部补齐发送完成、取消、错误和恢复语义。

**推荐候选方案：F429 内置 CAN2＋主控端 TJA1050，PB5 接收、PB13 发送；光流 SPI2 的 SCK 从 PB13 移到 PI1。** 这是核对当前代码及 V1 核心板引出后的最小改线方案之一：迁移一根现有光流信号线，保留 LCD、SDRAM、陀螺 I2C1、扫码及 USART1。最终接线须核验实际核心板版本、模块电路和排针方向。

迁移包含六类工作：

1. 核实并补齐电机端 CAN 硬件，统一七台参数。
2. 接入 TJA1050、电源、共地、总线与终端电阻，迁移光流 SCK。
3. 接入 CAN2 时钟、滤波、中断、发送完成及错误处理。
4. 实现官方 Emm CAN 拆包/重组，复用现有命令与解析结果。
5. 适配 MotorBus 停止优先、发送期限、取消和故障恢复。
6. 完成单机→双机→四轮→七轴验收及其它模块回归，再更新 README。

不在本阶段扩大到 CANopen、CAN FD、RTOS、底盘解算、导航融合、限位回零或比赛行为层。这些功能不会因换 CAN 自动出现。

## 3. 硬件改造

### 3.1 电机端先核对，再决定采购和接线

官方手册第 6 页说明 V2.0 可通过插拔通信小板更换通信类型，也存在集成收发芯片的版本。因此必须逐台确认：

- 实物驱动板版本与通信小板型号，是否已具有 CAN 收发电路。
- 若目前为纯 TTL 版本，按对应板卡规格装配兼容 CAN 小板或 CAN 版本驱动板；不能仅修改菜单就接 CANH/CANL。
- 不将主控端的一块 TJA1050 当成七台电机的全部 CAN 改造。每个 CAN 节点均需适配的收发电路；已有的不用重复购买。
- 改装、换线、测终端电阻均断电进行。更换通信小板与更换驱动主板是不同操作，不无故重刷固件或重置编码器校准。

逐台登记以下参数后再并网：

| 参数 | 计划要求 |
|---|---|
| P_Serial | CAN1_MAP；名称是电机端模式，与主控用 CAN2 不冲突 |
| CAN_Baud | 统一 500000 bit/s，先单机确认 |
| ID_Addr | 唯一地址 1～7，保持原用途 |
| Checksum | 0x6B，保持现有构帧方式 |
| Response | 先采用 Receive；Both/Reached 必须单独验证通知与 ACK 区分 |
| 固件与单位 | Emm；核对固件版本、S_Vel_IS、细分/脉冲含义，不因为换总线改变运动单位 |
| 终端电阻 | 记录每台是否带固定或可切换的 120 Ω，避免七台全部接入终端 |

依据：电机手册第 16、18～19、28 页。第 28 页原图明确 CAN 硬件下 `R/A/H → H`、`T/B/L → L`；该图中示例板标 V1.0，V2.0 小板的物理排针仍需实物核对。

### 3.2 引脚冲突审查与推荐配置

| 可选 CAN 引脚 | 当前占用 / 结论 |
|---|---|
| CAN1 PA11/PA12 | LCD R4/R5，不能直接套用 |
| CAN1 PB8/PB9 | LCD B6/B7；官方 F407 例程正是这一组，不可照搬 |
| CAN1 PD0/PD1 | SDRAM D2/D3，不能抢占 |
| CAN1 PH13 TX，PI9 RX | PH13 已是 LCD G2，不能仅看到 PI9 可用就判整组可用 |
| CAN2 PB5/PB6 | PB6 已作陀螺 I2C1 SCL |
| CAN2 PB12/PB13 | PB12 是扫码 TRIG，PB13 是光流 SCK |
| **CAN2 PB5 RX＋PB13 TX** | **PB5 当前应用未占用；PB13 可通过移动光流 SCK 释放，作为本计划首选** |

CAN 接收和发送引脚可分别选择其对应 AF9 功能，不要求采用例程中相邻的一对。芯片映射及 5 V 容忍类型以 [STM32F429 数据手册](https://www.st.com/resource/en/datasheet/stm32f429bg.pdf) 的引脚/复用表为依据；当前占用来自 `bsp_lcd.h`、`bsp_sdram.h`、`bsp_flow_spi.c`、`bsp_gyro_bus.c` 和 `qr_config.h`。

V1 核心板第 1 页排针图和第 2 页 MCU 网络核对结果：

| 信号 | 候选 MCU / 排针 | 迁移后连接 |
|---|---|---|
| CAN2_RX | PB5 / J7-50，AF9 | ← TJA1050 RXD |
| CAN2_TX | PB13 / J7-54，AF9 | → TJA1050 TXD |
| 光流 SPI2_SCK | **PI1 / J7-24，AF5** | → PMW3901 原 SCLK 线；原 PB13 SCLK 线移走 |
| 光流其余线 | PC2、PC3、PE3 | 保留 MISO、MOSI、CS |
| 陀螺 | PB6/PB7 | 保留 |
| 扫码 | PB10/PB11/PB12 | 保留 |
| K230/调试 | PA9/PA10 USART1 | 保留 |

当前 LCD G6 使用 PC7，未使用 PI1；当前 SDRAM 为 16 位，也未用 PI1 的 FMC_D25。实际连线需按 J7 的 1 脚标识确认，不能套用 H743 或 V2 核心板针号。若 PB5/PI1 实际被其它新增硬件占用，应重新分配，不静默覆盖。

### 3.3 TJA1050 与总线接线

| TJA1050 模块信号 | 计划连接 / 检查 |
|---|---|
| VCC | 规格匹配的 5 V 供电；原芯片工作电源 4.75～5.25 V，不能按普通 3.3 V 模块供电 |
| GND | 主控逻辑地及电机通信参考地；电机大电流回路另行布线 |
| TXD | PB13 CAN2_TX；3.3 V MCU 输出可满足原芯片输入高门限 |
| RXD | PB5 CAN2_RX；原芯片为 5 V 电源域输出，须核对模块是否有电平处理以及 MCU FT 引脚条件 |
| CANH | 七台 CAN 电机的 H 端；对应手册 CAN 模式下 R/A/H |
| CANL | 七台 CAN 电机的 L 端；对应手册 CAN 模式下 T/B/L |
| S（若引出） | 正常收发模式应为低；确认模块板载配置。高电平为静默，不能发送 |

原芯片支持 3.3 V 输入不等于所有模块引脚都输出 3.3 V。PB5 是 FT 数字引脚，使用数字复用、关闭内部上下拉，并核对数据手册的供电/掉电约束；避免模块有电、MCU 无电时通过信号脚反灌。若模块不是原芯片直连，应按该模块电路确认电平或加适配。[TJA1050 电气参数](https://www.nxp.com/docs/en/data-sheet/TJA1050.pdf)、[F429 引脚与电气限制](https://www.st.com/resource/en/datasheet/stm32f429bg.pdf)

采用一条 CANH/CANL 双绞主干，节点短支线连接，避开电机相线和大电流电源线。仅主干两个物理端点各放一只 120 Ω；模块已有终端时计入总数。断电且其它电路影响可忽略时，总线 H/L 间应约 60 Ω，不是每台电机都加 120 Ω。终端按物理位置设置，与电机地址无关。

```text
F429 CAN2 ── TJA1050 ── CANH/CANL 主干 ── 电机1 … 电机7
                         两个物理端点各120Ω
PB13 → TXD               每个电机节点具备CAN收发电路
PB5  ← RXD               主控与节点具备通信参考地
```

电机动力电源与模块 5 V 电源分别按其规格供电，不能将电机供电端直接接 TJA1050 VCC。已买的 TJA1050 不是 USB-CAN 分析仪；PC 抓包需要另有兼容适配器，可作为调试工具，不是运行必需品。

## 4. 协议适配：保留 Emm 命令，新增 CAN 封装

依据本地官方手册第 42～44、49～50 页及 `9. 例程_STM32F407/HAL库/Emm固件模式/CAN通讯/STM32F407_CAN通讯__多电机命令.rar` 中 `Src/can.c`，规则如下：

- 经典 CAN 2.0 扩展**数据帧**，29 位 ID；不是标准 11 位帧，也不是 CANopen 或 CAN FD。
- `ExtId = (电机地址 << 8) | 分包序号`，序号从 0 开始。
- 地址不再放入 Data；**每一包的 Data[0] 都重复功能码**。
- 原逻辑命令除地址、功能码后的字节，每包最多携带 7 字节；最后仍保留协议要求的 0x6B。
- CAN 帧自带 CRC，但不因此删除应用协议末尾 0x6B。

官方示例：

```text
原命令：01 36 6B
CAN： ExtId=0x0100，DLC=2，Data=36 6B

原命令：01 FD 01 0F A0 00 00 01 FA 00 00 00 6B
CAN0：ExtId=0x0100，DLC=8，Data=FD 01 0F A0 00 00 01 FA
CAN1：ExtId=0x0101，DLC=5，Data=FD 00 00 00 6B
```

现有四轮 `Emm_Wheels()` 生成 37 字节 `00 AA ...`，CAN 分为 **5 帧**：ID `0x0000～0x0004`，每帧功能码 AA＋7 字节；不是把 37 字节简单每 8 字节截断。现有容量 128 字节的逻辑命令最坏需要 `ceil((128-2)/7)=18` 帧，队列与期限必须按逻辑命令上限设计。

接收时，先检查 IDE、RTR、ID 合法范围、地址和 DLC，再按地址/功能码维护有界重组状态；校验包号顺序、长度和期限，丢弃缺包、乱序、重复冲突、超长或错误帧。第一包恢复 `[address, code, ...]`，续包去掉重复 code，仅在收到完整且符合已知长度的逻辑响应后交给原解析层。

不能将所有 CAN Data 直接拼进 UART 字节解析器，也不能“遇到 0x6B 就结束”，因为数据字段本身可能为 0x6B。第一阶段可仅支持当前使用的反馈/ACK 长度；其它响应明确拒绝并计数，后续再加。当前解析缓存只有 32 字节，不能因为命令容量为 128 就假定任意长反馈已支持。

至少覆盖版本、速度、位置、状态、使能 ACK、速度/位置/停止 ACK 和到位通知。不同节点响应可能交错，不得串轴。CAN ACK 位仅说明有节点在链路层确认帧，不证明目标电机接受命令；Emm 的 02 ACK 也不证明机械动作完成。

多电机 AA 命令仍保留官方“运动命令由地址 1 返回接收确认”的语义；不得因 CAN 可仲裁就改成等待四台各自 ACK。四轮是否执行、停车仍逐台看新鲜反馈。

### 5.2 HAL 与时钟配置

已核查工程：`HAL_CAN_MODULE_ENABLED` 已开启，但 Keil 当前指向 `Libraries/STM32F4xx_HAL_Driver/Src/Legacy/stm32f4xx_hal_can.c`，该源受未开启的 `HAL_CAN_LEGACY_MODULE_ENABLED` 控制。当前未调用 CAN 不代表已经可用。计划改为同仓库的 `Src/stm32f4xx_hal_can.c`，配套现有非 Legacy 头文件；无需整体升级 HAL。

建议 CAN2 初始配置：

| 项目 | 计划值 |
|---|---|
| 时钟源 | APB1 = 45 MHz；不是 APB1 定时器的倍频时钟 |
| 位速率 | 500 kbit/s |
| Prescaler / BS1 / BS2 / SJW | 6 / 12 TQ / 2 TQ / 1 TQ |
| 计算 | 45 MHz ÷ 6 ÷ (1＋12＋2) = 500 kbit/s，采样点约 86.7% |
| 工作模式 | 内部回环验证后改 NORMAL |
| 引脚 | PB5 / PB13 AF9；CAN1 只开必要时钟，不初始化其 LCD/FMC 引脚 |
| CAN1/CAN2 时钟 | 两者都使能，CAN2 依赖 CAN1 的共享资源 |
| 滤波 | 例如 SlaveStartFilterBank=14，CAN2 从 bank14 起配置；拒绝标准帧/远程帧并限制节点地址，软件再次检查 |
| 中断 | CAN2_RX0、CAN2_TX、CAN2_SCE；只有使用 FIFO1 才配置 RX1 |

CAN2 的共享滤波分区须显式配置，不能直接复制 CAN1 例程的 bank0；参考 [ST 双 CAN 滤波说明](https://community.st.com/stm32-mcus-60/stm32-in-dual-can-configuration-bxcan-filter-bank-explanation-and-relation-with-can2-start-bank-parameter-136737)。IRQ 优先级按现有传感器/串口调度预算选择，不照搬例程全部最高优先级。

官方 F407 例程是 Prescaler=14、BS1=4、BS2=1，套用本工程 45 MHz 会得到约 535.7 kbit/s，不能使用。本文值是计算起点，需实测波形、错误计数和实际总线稳定性。

### 5.3 非阻塞发送与接收

- 官方示例的 `while(HAL_CAN_AddTxMessage(...) != HAL_OK)` 和滤波初始化无限重试不能直接搬入当前协作式主循环。
- `send()` 接受整条逻辑命令时复制到持久缓冲，忙则立即返回；后台逐帧发送。先采用单帧在途策略保证包号顺序，后续若用三个 mailbox 必须重新验证仲裁/重传下的顺序。
- “mailbox 有空位”“HAL_AddTxMessage 返回 OK”“最后一帧获得发送成功”是不同事件。只有完整命令的所有分片成功，才能进入应答等待；失败必须先上报，不能以 busy 变为 0 冒充成功。
- TX 期限按 CAN 帧数、位时序与有界排队预算计算；现有 `20ms＋字节数/115200` 仅属于 UART。首期仍保留上层 10 ms 请求间隔、60 ms 应答与 120 ms 隔离，实测后再调整。
- ISR 只读取帧、记录接收时间/错误并入队；前台重组及更新 MotorBus。队列满必须计数并使受影响重组失效，不静默覆盖。
- RX、TX、恢复每次 Pump 都有工作量上限，主循环及时返回。帧入队时间用于新鲜度/STOP 证据判定，不能把积压的旧帧当成刚采到的新反馈。

### 5.4 STOP、重传与恢复是重点

CAN 硬件重传与应用级重发必须分开设计：重发一条相对位置命令可能产生额外位移。首期建议显式关闭无界自动重传，与官方例程方向一致；发送失败上报不确定状态，查询和幂等停止由有期限的应用策略决定重试，普通运动命令不自动重放。若以后启用硬件自动重传，必须有可证明的取消/期限机制，不能让旧速度命令在重连后突然发出。

计划保持并验证：

1. STOP 优先于普通待发动作。取消尚未发完的动作及硬件待发 mailbox，确认中止/完成竞态后再发送 STOP；收到 STOP 后不得继续补发该动作剩余分包。
2. 取消发生在最后一片已上总线时，要按“可能已经执行”处理，保留持续停车及反馈确认；不能报告“从未执行”。
3. 已有首次 STOP＋两次快速尝试、后续限频重试、公平轮转和零速/状态确认继续适用；发送失败不清除 stop_unconfirmed。
4. 保留 3 s UNKNOWN、STOP UNCONF 与新运动禁入；地址 6 升降轴不以 Disable 替代停车。
5. bus-off、TX 超时、FIFO 溢出、重组缺片时清理失效事务、锁定不确定运动，保持 STOP 意图；恢复要有退避，不能在 ISR 中反复初始化。
6. 第一版建议由前台管理 bus-off 恢复（明确配置 AutoBusOff 策略），清空旧运动发送队列/mailbox，恢复查询和未确认 STOP；不恢复旧动作、不自动触发缓存同步。恢复需要现场新鲜反馈和新的动作意图。
7. CAN 分包序号只表示一条命令内的包次，**不是事务序号**，迟到同码回复问题仍存在；保留隔离和证据时序。
8. 首期维持“接收不可用时不发送新命令、保留停止意图”的既有策略；若另做仅 TX 停车路径，应单独设计和验收。

CAN 断线、收发器掉电或 MCU 停机时，软件 STOP 无法保证送达。主控租约也不是电机内部通信看门狗；通信中断自动停车能力需要核对具体驱动固件，不能假设已支持。TJA1050 的 TXD dominant timeout 是总线保护，不是电机停车功能。

## 6. 分阶段实施与验收

| 阶段 | 工作与交付 | 进入下一阶段条件 |
|---|---|---|
| A 硬件确认 | 模块/七台通信小板清单、接线表、终端配置、参数记录 | 供电和电平核对完成，明确电机 CAN 硬件具备；未满足可继续纯软件工作，但不实物接总线 |
| B 静态与主机测试 | 完成 CAN 适配、两后端编译、分包/故障替身测试 | 单元/集成回归通过；无硬件时只能声明软件通过 |
| C 板上基础通信 | 回环，再接一台电机只读版本/速度/位置/状态；光流换 SCK 后复测 | 标识符/DLC/应答正确、无连续总线错误；光流、屏幕、扫码、陀螺正常 |
| D 单机低速动作 | 单机使能、10 RPM 限时动作、STOP，受控短距离位置运动 | 运行/停止/反馈符合要求，不用未标定脉冲执行 50 mm 全行程 |
| E 双机→四轮 | 节点交错反馈、四轮 AA 五帧与逐轮反馈；必要时单独启用保留的上电测试构建 | 无串轴、错包、重复动作；组 ACK 不冒充四轴完成 |

最低必要故障测试：

- 单帧查询、两片位置、五片四轮聚合及 128 字节边界；含数据值 0x6B。
- 错 IDE/RTR/DLC、包号跳跃/重复、不同地址交错、缺尾片、超时和软件队列溢出。
- 第二片/最后一片 TX 失败；“入 mailbox 成功但未上总线”；STOP 插入分包途中；取消与最后一片完成同刻。
- 首次 STOP 丢失后链路恢复：继续限频停车且必须新反馈确认；不只是进入 UNKNOWN。
- bus-off/无 ACK/节点掉电：其它服务继续，重连后不自动恢复旧速度、相对位置或同步触发。
- 只有其它节点 ACK、目标电机未在线：不得误判目标命令已接受。
- 七节点持续运行至少 30 分钟作为初次验收目标，记录 RX 丢帧、TEC/REC、bus-off、各字段最大年龄、STOP 延迟和主循环最大耗时；不是以“没有复位”代替数据验收。
- 慢 LCD/切页、扫码持续触发与 CAN 突发同时进行，核对 FLOW/GYRO 间隙、新鲜度和 CAN FIFO 峰值。

软件验证使用既有 `Scripts/test.ps1` 与 `Scripts/build.ps1 -Rebuild`，另加 CAN 测试；工具链为当前 AC5。新 STM32 相关文件不要直接放进被主机测试脚本通配编译的纯协议目录，或需调整源文件列表。交付注明编译固件提交、模块参数和实物测试范围。

## 7. 最终运行效果与性能边界

在硬件和上述验收均完成的前提下，预期效果为：

- 小车仍以原 1～7 地址及原用途工作，界面/行为层继续调用原 MotorBus API；电机控制与反馈经一条 CAN 总线往返。
- 默认上电只读，七节点反馈持续刷新；手动指定单轴或轮组运行，STOP 与停车未确认提示保留。四轮启动测试仍是可选测试功能。
- 1～4 可按 RPM 控制；5～7 可按现有位置脉冲模式操作，但毫米/角度换算、机械原点和限位仍需独立标定与开发。
- 光流使用 PI1 SCK 后保持原 counts 输出；陀螺、扫码、LCD、USART1 保持原业务和现有限制。
- 掉线能显示明确错误、限制新运动并保留停车意图；恢复后重新确认反馈，未执行的旧动作不会被自动补发。

预期收益是差分物理层、总线仲裁和硬件错误检测，便于七节点布线与诊断；具体抗干扰改善需实测。迁移不会修复原有的机械误差、陀螺固定偏置或光流未标定问题。

**不能承诺仅换 CAN 就得到更高的控制频率。** 当前 `MotorBus_Wheels()` 仍限制约 100 ms 一次，服务还有 10 ms 请求间隔、单活动事务及反馈期限。37 字节 TTL 发送约 3.21 ms；500 kbit/s 的五帧 CAN 仅线缆占用可估为约 1～2 ms，但仲裁、分片调度、主循环和电机处理都会增加延迟。首期目标是功能等价且可靠；需要更高频底盘闭环时，另按实测负载优化调度。

## 8. 回退与交接约束

- 保留 UART5 后端，使用编译期配置选择；不让 UART/CAN 两个后端同时向同一组电机发运动命令。
- CAN 版不初始化 UART5 的电机 DMA/中断；扫码 USART3 的 DMA 与统一 UART 回调仍保留。
- TTL 回退需要同时恢复电机通信小板/模式和 TTL 接线，不能只改软件宏；光流 SCK 采用配置选择并写清当前接线。
- 优先在 main 上按最小范围实现，实施前重新检查工作区变化；不覆盖并行行为层工作。本文不授权现在开始改代码或写电机持久化参数。
- CAN 是否作为默认总线，应在阶段 G 根据实物结果决定。当前 README 仍应明确“使用 TTL”；本文不取代其当前状态。

可用于后续对话的任务摘要：

> 在现有 F429 七电机工程上，以本计划为候选方案、以最新 README/源码为事实，最小改动加入 Emm CAN 后端。先核验 TJA1050 模块和逐台电机 CAN 小板；候选 CAN2 PB5/PB13，光流 SCK 移到 PI1。保留 MotorBus 动作/停车语义与 UART 回退，采用非阻塞拆包/重组、明确发送完成/取消/错误边界。不得照搬官方 PB8/PB9、F407 位时序或无限等待。完成两后端回归、Keil 构建并提供接线和实物验收步骤，报告最终运行效果与未验事项。没有硬件验证证据时不能宣称 CAN 实测通过。
