## 1. 结论与范围

**迁移可行，主要工作集中在板级接口适配、无屏操作入口、工程配置和重新联调。电机协议、扫码解析、光流与陀螺服务可以大部分保留。**

需要先修正“芯片相同”的前提：野火核心板是 **STM32F429IGT6（176 引脚、1 MiB Flash）**，本地 S2 原理图标注 **STM32F429VET6（100 引脚、512 KiB Flash）**。两者同属 F429，内核与主要外设兼容，但具体料号、封装、引脚数量和 Flash 容量不同。实物若采用另一料号，应以实物重新核对。[ST F429 数据手册](https://www.st.com/resource/en/datasheet/stm32f429ve.pdf)

这里将“全量迁移”定义为：保留当前工程已经实现的非显示功能及其操作能力，包括七节点电机服务、扫码/重扫、光流读取/清累计、陀螺读取/校准/归零、故障状态、手动台架操作和停止控制。RGB 显示、触摸、界面绘制、字体与显存链路不迁移。

以下项目属于**后续开发**，不能计入“已有功能迁完即获得”：K230 通信协议、两个舵机的控制、机构限位与回零、麦轮运动学、定位融合、路径规划和比赛动作状态机。迁移时为它们预留接口即可，若一并开发需另立任务与工期。

源硬件只按“野火 V1 核心板＋RGB 屏”理解，不假设存在野火底板上的电源、蜂鸣器、USB 转串口、IMU 或机器人接口。S2 的额外板载功能也不要求全部启用。

## 3. 建议接口分配

下表是按 S2 V2.1 图纸提出的**候选接线表**。插座脚号、端子朝向和电源必须在实物上核对后冻结；不以“都叫串口”推断可直接插接。

| 功能 | 野火现配置 | S2 建议分配 | 原理图依据与适配 |
|---|---|---|---|
| 七台串口步进电机 | UART5 PC12 TX / PD2 RX | **USART3 PB10 TX / PB11 RX** | 第 5 页七路步进口共接 PB10/PB11；保留地址 1～7、115200/8N1 与 MotorBus |
| 扫码串口 | USART3 PB10/PB11 | **UART5 PC12 TX / PD2 RX**，串口5 U13 | 第 3 页；保持 9600/8N1、组帧及会话规则 |
| 扫码 TRIG | PB12 | **PB0，H6-10**，普通 GPIO | 第 6 页；低有效，复位到初始化期间优先保持不触发电平；确认模组接口电平后接线 |
| PMW3901 SCK | SPI2 PB13 | **SPI1 PA5，H6-6** | 第 6 页 SPI1_SCK |
| PMW3901 MISO | SPI2 PC2 | **SPI1 PB4，H6-3** | 第 6 页 SPI1_MISO；使用 SWD，核对 JTAG 复用释放 |
| PMW3901 MOSI | SPI2 PC3 | **SPI1 PB5，H6-4** | 第 6 页 SPI1_MOSI |
| PMW3901 CS | PE3 | **PA4，H6-5**，软件片选 | 尽管图纸标 NSS，本方案配置为普通输出；初始化先置高 |
| ICM42688 SCL/SDA | I2C1 PB6/PB7 | **保持 PB6 H6-1 / PB7 H6-2** | 第 6 页板载各 4.7 kΩ 上拉到 3.3 V；核对模块上拉并联后的实际值 |
| 维护/日志 | USART1 PA9/PA10 | **保持 USART1，经 CH549F/USB1** | 第 3 页；先实测枚举、收发与供电关系 |
| K230（预留） | 拟用 USART1，协议未实现 | **USART6 PC6 TX / PC7 RX**，串口6 U7 | 避免与 CH549F 共驱动 USART1_RX；双方协议作为独立开发项 |
| 无屏状态指示 | 原野火 LED BSP | **PD0 板载 LED，低有效** | 第 1 页；重写板级 LED 定义，不能保留野火全部 LED 引脚 |
| 本地按键 | 当前主流程依赖触摸 | **PD1 用户按键，低有效** | 第 1 页；初期只作明确的停车/确认用途，详细操作走维护终端 |
| SWD | 现有下载器接核心板 | **PA13/PA14＋GND 等按 S2 下载口接线** | 第 1、3 页；核对外部下载器与板载下载电路的共享关系 |

### 3.1 为什么建议交换电机和扫码串口

S2 的七个步进插座在硬件上共用 PB10/PB11，不是七个独立 UART。继续保留当前 UART5 电机代码，不能让这些插座自动连到 UART5。使用现成七路接口时，电机改为 USART3 是最直接的方案；将扫码放到 UART5，则两组成熟串口逻辑都能保留。

备选方案是电机继续用 UART5，通过串口5外接独立配电/总线线束，扫码继续用 USART3。该方案固件改动较少，但不再直接使用 S2 七路步进接口，仍需处理接线与配电，不作为本计划首选。

### 3.2 电气与供电任务

- 第 5 页步进口带 BATT 和 GND，EN/PWM/DIR 图示未连接。应按电机 **TTL 通信端**重新制作线束，核对驱动器 R/A/H、T/B/L 的方向和端子定义；不能按脉冲接口直插。
- 七个电机反馈端共线并不自动证明电气兼容。逐台确认地址唯一、当前 Emm 固件、应答模式，以及未被寻址时 TX 的输出行为；必要时增加合适的总线接口，避免多个推挽输出争用。
- S2 的串口插座带 5 V 电源脚，不能据此认定信号为 5 V，也不能把 5 V 接到只允许 3.3 V 的传感器信号。PMW3901、当前 ICM 模块继续按 3.3 V 方案核验。
- 第 6 页 H5 电源排针混有 5 V 和 3.3 V。逐脚确认，不能把整排当成统一电压；PB0 等 H6 引脚也不要误作电源。
- 第 2 页有 BATT、5 V、3.3 V、标为 7 V 的电机/舵机电源与独立 5V/5A 输出。应核对电池范围、七电机峰值电流、接插件/铜箔承载、地回流、保护和散热。图纸标题中的额定值不作为实测能力。
- 两个 270° 舵机的完整型号和供电范围未确定。不得因 S2 有舵机接口就直接用标为 7 V 的电源；需要时另配合适电源。
- USB、下载器、电池和外部传感器电源同时连接时，检查反向供电及共地。保留七电机独立配电的可能性，不强制所有功率电流经过 S2。

## 4. 软件工程修改清单

### 4.1 建立 S2 独立构建目标

建议增加 `S2_HEADLESS` 目标及板级配置，不覆盖已经可用的野火目标；输出目录独立，避免误烧录。可建立 `board_config.h` / `bsp_board.c` / `bsp_hal_msp.c`，集中描述接口归属、LED、按键和无屏开关。

1. 芯片目标改为 `STM32F429VETx`；保留 `STM32F429xx`、F429 启动文件和现有 HAL/CMSIS 版本。检查并清理与显示板相关的 `USE_STM32F429I_DISCO` 宏及其引用。
2. Flash 配置为 `0x08000000` 起、长度 `0x80000`，上界 `0x0807FFFF`；核对 IROM、链接选项、下载算法和生成地址范围，不能只改设备名字。
3. 常规 SRAM 为 `0x20000000` 起 192 KiB，CCM 为 `0x10000000` 起 64 KiB。UART DMA 缓冲保持在常规 SRAM；栈、堆及静态状态不依赖外部 SDRAM。检查启动文件、scatter/map 和 `DATA_IN_ExtSDRAM` 等开关。
4. 主时钟保持 25/25×360/2=180 MHz、APB1=45 MHz、APB2=90 MHz，检查 OverDrive 返回状态与失败诊断。工程元数据中的 CLOCK 字段和 `HSE_VALUE` 同步核对，实际运行频率由 RCC 配置验证。
5. 当前 PLLQ=7 不产生精确 48 MHz；本计划通过板载 CH549F 使用 USB 维护，不新增 MCU USB 功能。若后续启用 MCU USB/其他相关外设，另核对 48 MHz 时钟。
6. 更新 `Scripts/build.ps1`：允许选择目标与独立日志/输出路径。第一次完整构建要求 0 error / 0 warning，并保存目标、编译器版本、commit、宏和资源占用。

### 4.2 去屏及解除隐含依赖

| 文件/模块 | 计划处理 | 必须保留或另行迁出的逻辑 |
|---|---|---|
| `User/main.c` | S2 不调用 `GTP_Init_Panel`、`LCD_Init`、各图层初始化及 `GTP_SetRuntimeMode` | HAL/时钟、通信初始化、各服务初始化与主循环 |
| `User/app/qr_app.h/.c` | 把服务聚合状态与 `QrUi` 分开；去掉触摸和绘图调度 | 电机调度、扫码触发与 pump、Flow/Gyro 服务、停车与校准门控、可选上电测试状态机 |
| `User/app/qr_ui.*`、`motor_ui.*`、`flow_ui.*`、`gyro_ui.*` | S2 目标排除界面实现 | 将必要的操作语义移入应用命令层；业务 API 不反向依赖 UI 枚举/选中轴 |
| `User/app/app_runtime.*` | 拆出/保留 `AppClock_Now`，S2 排除触摸状态 | HAL 毫秒时基与新鲜度判断 |
| `User/stm32f4xx_it.c` | 去触摸包含项、`GTP_IRQHandler` 及其 LED 操作 | SysTick、异常处理；若新增 PD1 EXTI，建立独立入口 |
| `User/lcd`、`touch`、`fonts`、`sdram` | S2 构建排除，并审查相应 HAL 模块的使用 | 无屏业务不得访问帧缓冲地址或初始化不存在的 SDRAM |
| `User/flash/bsp_spi_flash.c` | 无显示字库/业务存储需求时排除 SPI5 Flash 驱动 | **先迁出 `HAL_SPI_MspInit` 的光流分支**，当前光流依赖此文件分发 MSP |
| `User/led` | 为 S2 重写或按板型选择 | PD0 状态指示，不把原板 LED GPIO 批量初始化到 S2 |

当前 `manual_action()` 从 `a->ui.selected`、`a->ui.test_action` 取得参数，启动测试也写 `a->ui.redraw`。因此只给 LCD 函数做空实现仍保留了业务/UI 耦合；应让新的命令对象显式携带轴号、动作、参数和来源，并统一调用 MotorBus/Gyro/Qr 服务。

源码中未见现有核心业务把任务或校准数据持久化到 SPI Flash；当前陀螺正常校准偏置在 RAM 中。计划不要求替 S2 新增外部 Flash。若后续需要保存参数，作为独立设计明确存储布局、校验和掉电策略。

### 4.3 串口、DMA 和回调整体迁移

推荐映射如下，依据 ST RM0090 的 DMA1 request mapping；上线前用实际构建、寄存器和波形再次核验。[ST RM0090](https://www.st.com.cn/resource/en/reference_manual/rm0090-stm32f405415-stm32f407417-stm32f427437-and-stm32f429439-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)

| 用途 | S2 外设 | DMA | IRQ |
|---|---|---|---|
| 电机 RX | USART3 | DMA1 Stream1 / Channel4 | USART3、DMA1_Stream1 |
| 电机 TX | USART3 | DMA1 Stream3 / Channel4 | USART3、DMA1_Stream3 |
| 扫码 RX | UART5 | DMA1 Stream0 / Channel4 | UART5、DMA1_Stream0 |
| 维护口 | USART1 | 首阶段可用中断接收＋有界发送队列 | USART1；若引入 DMA 再分配资源 |
| K230 预留 | USART6 | 暂不启用；协议阶段再确定 | 暂不启用 |

涉及 `bsp_motor_uart.c`、`bsp_qr_uart.c`、`bsp_uart_callbacks.c`、`bsp_debug_usart.c`，以及主机测试替身。必须一起修改 Instance、GPIO/AF、RCC reset/enable、DMA 关联、IRQ 名称、优先级、NVIC disable/clear/enable、故障恢复和 HAL 回调路由。

特别检查：电机 TX 从 Stream7 改为 Stream3；不能只交换 RX 的 Stream0/1。现有 IRQ 直接定义在 UART BSP 内，不能又在 `stm32f4xx_it.c` 定义第二份。共享 `HAL_UART_MspInit` 与 HAL UART 回调均保持单一入口。

保持现有接收 DMA 启动校验、PE/FE/NE/ORE 处理、半帧丢弃、隔离窗、持久 TX 缓冲和 STOP 重试/反馈确认，不换成厂家例程中的简单阻塞收发。`MotorBus` 仍是电机总线唯一发送者。维护口优先级及吞吐应受限，避免大量日志影响电机反馈和传感器服务。

### 4.4 传感器适配

**光流：**只改变 `bsp_flow_spi.c` 的外设、引脚与 MSP 归属，保留 PMW3901 初始化序列、Burst 格式和服务层。SPI1 在 APB2，建议先设 `/128`，90 MHz/128=703125 Hz，匹配旧 SPI2 45 MHz/64 的速率；保留 Mode 3、8 bit、MSB、软件 CS、2 ms 事务超时。共享 DWT 只使能、不清零。验证 PB4 复用、MISO/MOSI 方向和模块供电。

**陀螺：**I2C1 PB6/PB7、100 kHz、地址 0x68 可先保持；核对 CS 高、SA0 低、上拉及 WHO_AM_I。保留有限等待与总线故障恢复。临时 15.86°/s 补偿是原台架条件下的处理，换板供电/安装后须重新测静止漂移；不能据此声称已校准，也不能通过删除 CAL 门控来让测试通过。

两模块安装位置、方向或高度变化时，重新核对轴映射与测量结果。光流现阶段仍输出 counts、陀螺仍为相对积分角；转换到毫米或融合导航不属于此次功能等价迁移。

## 5. 无屏操作与诊断方案

首阶段采用“USB 维护终端＋PD0 状态灯＋PD1 按键”。维护端可以用串口工具，不要求先开发图形上位机。命令解析、执行权限与诊断快照分层，避免界面删掉后功能只能靠改源码触发。

| 原界面能力 | 拟提供的无屏能力 | 验收要求 |
|---|---|---|
| 四页状态、MORE/DETAIL | `status`、`motor status <id>`、`flow status`、`gyro status` | 输出时间戳/年龄、valid/stale、故障、停止未确认、模式及当前固件配置 |
| MANUAL 与选轴/选动作 | `mode manual/read_only`、显式轴号与受限动作参数 | 上电 READ ONLY；拒绝越界参数、过期反馈和未确认停止后的运动请求 |
| RUN ONCE | 有唯一确认响应的一次动作命令 | 完整新命令才执行；不因终端重连、日志重发或重复按键自动重放 |
| STOP ALL/WHEELS/AXIS | 独立 `stop` 命令，PD1 可请求全体停车 | 停止可在只读模式请求，优先处理；返回待提交/未确认/已确认，不把 ACK 当停车证明 |
| RESCAN | `qr rescan` | 调用原会话边界 API，清旧缓冲和重新同步；扫码不触发运动 |
| FLOW CLEAR | `flow clear` | 仅清软件累计，保留原有统计/段号语义说明 |
| GYRO CAL/ZERO | `gyro cal`、`gyro zero` | 仍调用原 API 和各自门控；CAL 保留电机静止/反馈新鲜度条件，ZERO 不等同偏置校准 |
| 上电测试 | 独立台架构建选项，默认关闭 | 无屏版本也不允许上电即运动；开启时有明确固件标识和原停止路径 |

以上命令名字只是接口草案，实施时冻结协议。建议接收队列和命令长度有上限，发送日志有频率/带宽上限；禁止用逐字符、最长 1000 ms 等待的现有 `printf/fgetc` 直接承担高频运行期诊断。保留统计并允许按需查询，避免“去掉绘图，却新增长时间串口阻塞”。

操作命令统一交给应用层，不直接调用 HAL 发送电机帧。运动命令仍受速度/时间/脉冲边界约束；通信断开时的动作租约、停止请求和模式退出规则要明确并测试。

PD1 软件停车受 MCU、调度和通信链路约束，不等同独立急停。特别是升降轴 6：保留现有保持/停止语义，不能用全体 Disable 代替停车。独立断能、机械保持及故障停车方案应结合实际机构验收。

## 6. 分阶段实施与交付

以下工期为一名熟悉该工程的开发者、板卡和仪器齐备时的初步估算；不含采购、改 PCB、机构加工和比赛算法开发。

| 阶段 | 工作内容 | 交付物 / 放行条件 | 估算 |
|---|---|---|---|
| P0 基线与接线冻结 | 核对实物料号/板版、保存源固件与参数；核对电源和七机总线；冻结接口表 | 引脚/电源/线束表，已知问题表，可回退源工程快照 | 0.5～1 天 |
| P1 无屏最小系统 | S2 目标、Flash/RAM、启动/时钟、LED/维护口；彻底排除显示依赖 | 可独立启动的无屏固件；不接屏/SDRAM也不阻塞；map 合规 | 1～2 天 |
| P2 应用与 BSP 迁移 | 拆 UI、加入命令层；UART/DMA/回调、扫码 TRIG、SPI1、I2C1 | 各模块可单独读状态和执行原操作；错误可诊断 | 2～3 天 |
| P3 单模块回归 | 先扫码/传感器，再电机查询、使能和低速限时动作 | 主机回归报告＋单模块接线、日志和波形 | 1～2 天 |
| P4 多模块/七机集成 | 1→2→4→7 节点；故障注入；维护口日志压力；电源验证 | 多设备同时在线报告、故障行为报告和最终固件 | 2～4 天 |
| P5 整理与交接 | 更新文档、参数清单、烧录步骤和待办；回归野火目标 | 可复现工程、HEX/AXF/map、接线图、测试记录 | 0.5～1 天 |

**总量约 7～13 个工作日。** 这是保留已有非显示能力并完成必要回归的范围；若只要求“串口能打印、传感器有数”，可以更快，但不能当作全量迁移验收。七电机总线电气不兼容、供电需重做或板版不同，会增加硬件整改时间。

建议人员分工：固件负责人负责构建、接口和服务；硬件/装调负责人负责线束、供电和测量；测试记录可由同一人分阶段承担。不要求为迁移引入新的软件框架。

## 7. 验收方案

### 7.1 构建和启动

- S2 目标 0 error / 0 warning；链接范围不越过 512 KiB Flash；DMA 缓冲位于可访问 SRAM；没有运行期 LCD/触摸/SDRAM/SPI5 Flash 依赖。
- 验证 HCLK、APB、SysTick；示波器/逻辑分析仪核对串口实际波特率、TRIG 周期和 SPI 时钟。正常冷启动及反复复位能进入 READ ONLY；不存在默认上电运动。
- 原野火目标仍可构建，避免共享重构损坏现有回退路径。记录每次测试对应的 commit、目标和宏。

### 7.2 功能等价

- 扫码：合法/非法/重复输入、换行、跨 DMA 边界、重扫和断线恢复；15 字符任务格式与会话锁定保持一致。读取 PB0 触发波形验证 1000 ms 周期、800 ms 低电平配置。
- 光流：身份、初始化、运动方向、低质量不累计、清累计和恢复段号；若安装不变，和原板同条件数据对照，不额外宣称毫米精度。
- 陀螺：身份、新样本、静止漂移、相对转角、CAL 拒绝/通过条件及 ZERO；分别记录临时固定补偿模式与真实校准模式结果。
- 电机：先只查询单节点，再低速限时点动；双节点顺序动作后验证多节点调度。同步、四轮聚合及七机并发是单独用例，不能由“七个地址都能查询”替代。
- 所有原触摸操作有无屏等价入口，且不会绕开服务层约束。状态中能辨识未确认停车、反馈过期、传感器恢复和临时补偿。

### 7.3 异常与性能

- 覆盖 UART ORE/FE 等错误、RX DMA 启动失败、错误半帧/迟到帧、扫码溢出、电机离线、I2C NACK/总线占用、SPI 超时及恢复；运行期不自动重放动作。
- 覆盖 STOP 在总线忙、RX 不可用、重复请求、反馈迟到、无反馈时的行为。保留“RX 不可用时暂不能发送 STOP、意图持续保留”的当前限制，不在迁移后误报保证停车。
- 七机、扫码、100 Hz 目标传感器服务和日志同时运行时，记录主循环最大间隔、有效采样率、反馈年龄、DMA/队列溢出、超时/重试数；阈值沿用当前服务配置，出现 STALE 或长期饥饿需解决后放行。
- 建议连续运行不少于 30 分钟，并做受控掉电/重启/插拔测试；无无故复位、不可恢复挂起和非预期动作。时长是本计划的工程验收建议，不代表已达到。

现有 `Scripts/test.ps1`、`test_flow.ps1`、`test_gyro.ps1` 可复用。需要补上“无屏命令到原业务 API”的集成测试及新 UART/SPI 映射的适配测试。旧测试大量依赖 UI 与板级替身，应为两种目标分组；不能因为删除 UI 导致测试不编译，就把相关业务用例一并删除。主机测试不能替代 AF、DMA、电平与供电实测。

## 8. 主要风险与待确认项

| 风险 | 当前证据 / 未决点 | 应对 |
|---|---|---|
| S2 实物与 V2.1 图纸不同 | 尚未核对实物照片、丝印和芯片 | P0 先确认；本文脚号暂不作为直接施工指令 |
| 七路电机接口被误认为七个串口 | 图纸显示共用 USART3 | 统一 MotorBus，逐台地址/应答与电气核验 |
| 去屏同时删掉操作功能 | `QrApp` 明确依赖 UI 状态与枚举 | 先建立命令层，再排除 UI |
| 删除 Flash 后光流失效 | `HAL_SPI_MspInit` 在 Flash 文件 | 移到公共 MSP 文件并验证 SPI1 GPIO/时钟 |
| UART 只改句柄、未改恢复路径 | 当前 BSP 多处写死 IRQ/Stream | 用映射表逐项检查初始化、IRQ、清标志和恢复 |
| K230 与维护 USB 串口争用 | USART1 接 CH549F，原工程又拟接 K230 | 预留 USART6，协议另立项 |
| 供电/回流导致复位或传感器异常 | 尚无七机峰值电流与整车供电测量 | 分阶段增载，测 MCU/传感器供电与地噪声 |
| 原有未验证能力被当成迁移成果 | 当前只完成部分实物联调 | 验收报告标注原板已验证、S2 新验证和仍未实现 |

开工前至少冻结：S2 版本/MCU、七机驱动参数、模组供电/连接器、维护口可用性、K230 接口安排，以及两个舵机/限位是否只预留。后两者不阻止已有功能迁移，但会影响最终剩余 IO 预算。

若需要预留两个舵机，可优先评估第 5 页 **PC8/TIM8_CH3、PC9/TIM8_CH4**；剩余限位可从未占用扩展 GPIO 中分配，待数量与有效电平明确后冻结。PB8/PB9 接电源控制电路，不作为无约束空闲 IO。不要照搬整套 S2 示例的 GPIO/TIM 初始化，否则可能误启用板载功率输出。

## 9. 完成定义与最终交付

迁移完成应同时满足：S2 无屏独立启动；当前已实现的非显示服务与操作入口全部可用；板级映射、电源与总线经过核验；构建和必要回归通过；七机尚未通过的能力被明确记录；源板工程可回退。

应交付：

1. 独立 `S2_HEADLESS` 构建目标、板级配置及对应 HEX/AXF/map。
2. 核实后的引脚表、带方向和电压的线束表、实际供电图。
3. 无屏命令说明、状态/错误码说明、默认配置和操作流程。
4. 模块回归、七机集成、异常注入和运行性能记录。
5. 仍未实现的 K230、舵机、限位/回零、导航与比赛行为层任务清单。
