# 比赛纯调度框架（未接入执行器）

更新：2026-11-04；依据 main / `f14be37` 的 `qr_app.c`、`mission.c`、`mission_config.c` 和 `test_mission.c` 静态核对。框架于 2026-10-27 合入，未接入 K230 通信。

保留 mission.c/h 的两批搬运步骤、三槽逻辑状态、三件全部粗加工放完再取回的屏障、同色码垛映射、一次启动、停止与失败处理。mission_config 提供空路线配置及验证函数，未填写路线；`QrApp` 和 `Mission_Start` 尚未调用这些配置函数，不能把它们描述为已接入的导航或 START 校验。框架仍使用固定启停区2约定，正式部署前需要确认起点。

正常应用以全零 MissionPort 初始化。没有 blocked/begin/poll/stop 执行接口，因此 START 拒绝，既不会移动底盘，也不会抓放。比赛页仅用于展示未完成状态。未合入 mission_runtime、视觉协议、USART1 DMA或K230心跳；原USART1调试行为保持不变。

后续接入：通过 MissionPort 提供就绪检查、动作提交、按 request_id 查询完成及停止回调；真实扫码结果也由执行器交回。只有完整动作结束才返回 SUCCEEDED，不把入队或ACK当作到位。连接之前还须完成应用层独占控制仲裁、实际路线与抓放姿态、K230按钮READY/START握手，以及舵机动作时间验证。

统计口径：SOURCE_TO_SLOT和ROUGH_TO_SLOT各累计外部抓取；SLOT_TO_ROUGH和SLOT_TO_STORAGE各累计对外放置。每批外部抓取 6 次、对外放置 6 次；两批合计抓取 12 次、放置 12 次，车载槽内部抓放不重复计数。均为动作完成推定，不是物料反馈。

当前通用动作超时：扫码 15000 ms，其余每个动作 90000 ms；超时转 FAULT 并调用 stop。该超时不是整场 180 s 计时；代码尚未实现整场时限。规划中的“首版不做专用空载对心超时处理”不等于当前框架无限等待，接入执行器前需协调。框架成功接受一次 START 后，结束、失败或取消均不允许再次 START；再次运行须由后续生命周期管理显式重新初始化。
